Repositorio base - Aplicación del hospìtal

Guía educativa para comprender la estructura, permisos, sesiones, rutas y creación de módulos.

1. Objetivo del repositorio

Este repositorio contiene una versión educativa y reducida de la aplicación desarrollada en PHP, MySQL, PDO, Bootstrap 5 y JavaScript.

Su finalidad es permitir que estudiantes desarrollen nuevos módulos respetando la arquitectura original de la aplicación.

Importante: este repositorio no contiene datos reales de pacientes, personal, usuarios institucionales, claves, tokens, archivos médicos, documentos administrativos reales ni información sensible.

6. Lógica principal de rutas

El enrutamiento de la aplicación se realiza desde: 

admin/template/rutas.php

Cada módulo se invoca mediante el parámetro modulo en la URL: 

index.php?modulo=nombre_modulo

Ejemplo:

index.php?modulo=notas

El archivo rutas.php recibe ese valor, valida el permiso correspondiente y carga la vista indicada. 

case "notas":
    validar_permiso($_SESSION["notas"] ?? 0);
    include "forms/notas.php";
    break;

7. Lógica de permisos, sesiones y vistas

La aplicación utiliza un sistema simple de permisos basado en columnas de la tabla admin. Cada permiso es una columna TINYINT(1).

Ejemplo de columnas de permisos:

admin
debug
miperfil
menu_usuarios
nuevo_usuario
editar_usuario
usuarios_activos
notas
paginas_ayuda
en_construccion

Cuando un usuario inicia sesión correctamente, login.php consulta la tabla admin y carga esos permisos en variables de sesión. 

$_SESSION["notas"] = $usuario->notas;
$_SESSION["nuevo_usuario"] = $usuario->nuevo_usuario;
$_SESSION["editar_usuario"] = $usuario->editar_usuario;

Luego, el sistema utiliza esas variables para decidir si el usuario puede acceder o no a un módulo.

Relación completa

Elemento Ejemplo
Columna en tabla admin notas
Variable de sesión $_SESSION["notas"]
URL del módulo index.php?modulo=notas
Archivo cargado admin/forms/notas.php
Acciones del módulo admin/app/documentos/
Para que un módulo funcione correctamente deben coincidir la columna de permiso, la variable de sesión, la ruta y el archivo de vista.

8. Cómo agregar un nuevo módulo

Paso 1: crear la columna de permiso

Ejemplo para crear un módulo llamado reclamos:

ALTER TABLE admin
ADD COLUMN reclamos TINYINT(1) NOT NULL DEFAULT 0;

Paso 2: cargar el permiso en sesión

En login.php, luego de validar el usuario:

$_SESSION["reclamos"] = $usuario->reclamos;

Paso 3: agregar el permiso al formulario de usuarios

En:

admin/forms/nuevo_usuario.php
admin/forms/editar_usuario.php

Agregar un switch:

<div class="form-check form-switch mb-1">
    <input type="checkbox" class="form-check-input" name="reclamos" id="reclamos">
    <label class="form-check-label" for="reclamos">Reclamos</label>
</div>

Paso 4: guardar el permiso

En:

admin/app/usuarios/registrar.php
admin/app/usuarios/editar.php

Recibir el valor:

$reclamos = boton_switch($_POST["reclamos"] ?? 0);

Y agregarlo al INSERT o UPDATE correspondiente.

Paso 5: crear la vista

admin/forms/reclamos.php

Paso 6: registrar la ruta

En admin/template/rutas.php:

case "reclamos":
    validar_permiso($_SESSION["reclamos"] ?? 0);
    include "forms/reclamos.php";
    break;

Paso 7: agregar acceso visual al menú

En admin/template/sidebar.php o en el archivo de menú correspondiente:

<?php if ($_SESSION["reclamos"] == 1) { ?>
    <a href="index.php?modulo=reclamos">Reclamos</a>
<?php } ?>

10. Seguridad básica

  • No subir credenciales reales.
  • No subir archivos reales dentro de docs/.
  • No subir bases de datos productivas.
  • Usar password_hash() y password_verify().
  • Usar consultas preparadas con PDO.
  • Validar permisos antes de cargar cada módulo.
  • Escapar salidas HTML con htmlspecialchars() cuando corresponda.

12. Resumen para estudiantes

Para crear un módulo nuevo no alcanza con crear un archivo PHP. Hay que integrarlo a la lógica de la aplicación.

  1. Crear la columna de permiso en admin.
  2. Cargar ese permiso en sesión desde login.php.
  3. Crear la vista en vistas/.
  4. Crear las acciones en app/nombre_modulo/.
  5. Registrar la ruta en template/rutas.php.
  6. Agregar el acceso en el menú.
  7. Probar con un usuario que tenga el permiso habilitado.
La regla de oro: el nombre del permiso, la sesión, la ruta y el archivo deben ser coherentes (Idénticos).
