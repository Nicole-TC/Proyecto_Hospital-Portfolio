Módulo de Circuito Quirúrgico

Manual de Usuario y Estado del Proyecto

1. Módulos Implementados

El menú "Circuito Quirúrgico" (http://149.50.137.127:8080/admin) ofrece acceso a los siguientes módulos completamente operativos:

Dashboard

Métricas y monitoreo del circuito: pacientes en circuito, aptos para operar, alertas de demora y tiempo promedio.

Admisión de Pacientes

Ingreso de pacientes al circuito. Busca automáticamente por DNI: si existe, completa los datos; si no, habilita el formulario. Carga catálogos de cirugías, cirujanos y estudios asociados desde la base de datos. Al confirmar, registra al paciente y genera las órdenes para todas las postas del circuito.

Seguimiento de Postas

Control del estado de cada posta prequirúrgica (Admisión, Laboratorio, Cardiología, Imágenes, Pre-Anestesia) con indicadores visuales. Incluye modal de expediente clínico con detalle de estudios realizados y línea de tiempo de auditoría del paciente.

Lista de Espera

Pacientes con apto médico listos para programación quirúrgica. Muestra DNI, paciente, cirugía, fecha de apto y estado (Apto Quirúrgico, Pendiente, Rechazado) con badges de color. Incluye botón para iniciar la programación de cirugía.

Agenda de Turnos

Calendario semanal con navegación entre semanas. Al seleccionar un día se despliega el panel de turnos. Incluye buscador de turnos por paciente (DNI, nombre, apellido) y modal para crear nuevos turnos con verificación de DNI en tiempo real contra el servidor.

Gestión de Usuarios

CRUD completo con estadísticas (totales por rol), tabla paginada con buscador por DNI/nombre/apellido/email. Formulario de carga/edición con verificación de DNI contra servidor, validaciones en tiempo real, roles (Administrador, Recepcionista, Cirujano) y datos profesionales para cirujanos (especialidad, matrícula).

Auditoría Global

Historial de actividades del sistema con filtros por texto libre y fecha. Visualización en tabla con columnas: Fecha/Hora, Usuario, Rol, Acción, Paciente, Detalles. Incluye contador de resultados y mensaje cuando no hay coincidencias.

Gestión de Pacientes

CRUD completo con estadísticas (total, en espera, en cirugía, completados). Tabla paginada con buscador por DNI/nombre/apellido/teléfono. Edición de campos del paciente con formulario que bloquea el DNI. Incluye baja lógica de pacientes.

Especialidades

Catálogo de especialidades y subespecialidades médicas con relación padre-hijo. CRUD completo con estadísticas (total registros, especialidades, subespecialidades), tabla paginada con búsqueda, modal para crear/editar con selector de tipo y especialidad padre. Eliminación con confirmación.

Órdenes Médicas

Gestión de órdenes médicas del circuito quirúrgico. Permite visualizar, crear y dar seguimiento a las órdenes generadas durante el proceso de admisión y postas prequirúrgicas.

2. Seguridad y Validaciones

El módulo cuenta con una doble capa de seguridad (Frontend + Backend) en todos los formularios críticos:

Frontend (JavaScript)
  • Verificación de DNI en tiempo real: En Admisión, Usuarios y Agenda, se consulta el servidor al escribir el DNI. Si ya existe se bloquea el formulario (o auto-completa según el caso).
  • Sanitización en tiempo real: DNI y teléfono solo aceptan dígitos; nombre y apellido solo mayúsculas con acentos y Ñ; email se fuerza a minúsculas y se filtran caracteres inválidos; código postal alfanumérico en mayúsculas.
  • Sanitización de pegado (paste): Todos los campos relevantes interceptan el evento paste, limpian el contenido y lo reinseran ya sanitizado.
  • Validación de fecha: Fecha de nacimiento no puede ser futura; en usuarios se exige mayor de 18 años y máximo 110 años.
  • Bloqueo de formulario: En modo creación, todos los campos permanecen deshabilitados hasta que el DNI sea verificado como disponible contra el servidor.
  • Feedback visual en tiempo real: Cada campo muestra icono y mensaje indicando si el valor es válido (verde) o inválido (rojo).
  • Control de submit: Antes de enviar se re-ejecutan todas las validaciones; si hay errores se hace scroll al primer campo inválido.
Backend (PHP)
  • Control de sesión: Los endpoints críticos validan $_SESSION['id'] y rechazan peticiones sin sesión activa.
  • Restricción de método HTTP: Solo se acepta POST para operaciones de escritura; GET para consultas. Métodos no permitidos devuelven HTTP 405.
  • Validación de datos duplicada: Todas las reglas del frontend se replican en el backend (formato de DNI, nombre, apellido, email, teléfono, código postal, fecha).
  • Entrada JSON segura: Los datos se reciben como JSON desde php://input y se parsean de forma controlada.
  • Escapado de salida: Se utiliza htmlspecialchars() con ENT_QUOTES y UTF-8 en vistas que renderizan datos del usuario.
  • Manejo de errores: Todos los bloques críticos están envueltos en try/catch con mensajes de error seguros (sin exponer detalles internos).
